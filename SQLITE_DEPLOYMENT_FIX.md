# Исправление: SQLite не копируется на сервер при деплое

## Проблема
При обновлении сайта SQLite база данных с локального компьютера могла копироваться на сервер, что приводило к:
- ❌ Перезаписи продакшн базы данных
- ❌ Потере данных на продакшене
- ❌ Конфликтам между локальной и продакшн базой

## Решение

### ✅ Что было сделано:

1. **Улучшен .gitignore**
   - Добавлены правила для исключения всех SQLite файлов
   - Исключена директория `Spring Boot/data/`

2. **Создан скрипт деплоя `Spring Boot/deploy.sh`**
   - Копирует ТОЛЬКО JAR файл
   - НЕ копирует директорию `data/` с SQLite
   - Проверяет целостность файла

3. **Обновлен application.yml**
   - Поддержка переменных окружения для MySQL
   - Автоматическое переключение между SQLite (разработка) и MySQL (продакшн)

4. **Создан application-production.yml**
   - Явная конфигурация для MySQL в продакшене

5. **Обновлен docker-compose.yml**
   - Явно указаны переменные для MySQL
   - Добавлен комментарий о том, что data/ НЕ монтируется

## Как это работает

### Локальная разработка:
```yaml
# Используется SQLite (по умолчанию)
spring.datasource.url=jdbc:sqlite:./data/cargodb.sqlite
```

### Продакшн (docker-compose):
```yaml
# Переменные окружения переопределяют SQLite на MySQL
SPRING_DATASOURCE_URL=jdbc:mysql://mysql:3306/CargoDB
SPRING_DATASOURCE_DRIVER_CLASS_NAME=com.mysql.cj.jdbc.Driver
HIBERNATE_DIALECT=org.hibernate.dialect.MySQL8Dialect
```

## Использование

### Деплой backend:

```bash
cd "Spring Boot"
./deploy.sh
```

Скрипт:
- ✅ Собирает JAR
- ✅ Копирует только JAR на сервер
- ✅ НЕ копирует SQLite файлы

### На сервере:

```bash
# Убедитесь, что docker-compose.yml использует MySQL
docker-compose up -d

# Проверьте логи
docker-compose logs backend | grep -i "datasource\|mysql\|sqlite"
```

## Проверка

### Убедитесь, что SQLite не копируется:

1. **Проверьте .gitignore:**
```bash
git check-ignore "Spring Boot/data/cargodb.sqlite"
# Должно вернуть путь к файлу (значит игнорируется)
```

2. **Проверьте скрипт деплоя:**
```bash
grep -i "data\|sqlite" "Spring Boot/deploy.sh"
# Не должно быть упоминаний о копировании data/
```

3. **Проверьте на сервере:**
```bash
# На сервере не должно быть SQLite файлов
ssh root@93.125.114.252 "find /opt/fluvion -name '*.sqlite' -o -name '*.db'"
# Должно вернуть пустой результат
```

## Важные моменты

### ✅ Что правильно:
- SQLite используется только локально для разработки
- MySQL используется на сервере через docker-compose
- JAR файл не содержит SQLite базу
- Скрипт деплоя не копирует data/ директорию

### ❌ Чего избегать:
- НЕ копируйте вручную директорию `data/` на сервер
- НЕ коммитьте SQLite файлы в git
- НЕ монтируйте `data/` в docker-compose volumes
- НЕ используйте SQLite на продакшене

## Структура базы данных

### Локально (разработка):
```
Spring Boot/
  └── data/
      └── cargodb.sqlite  ← Только локально!
```

### На сервере (продакшн):
```
Docker Volume:
  └── mysql-data:/var/lib/mysql  ← MySQL база в контейнере
```

## Дополнительная защита

